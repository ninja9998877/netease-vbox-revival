# 07 · 危险操作清单

> ★ **动手前先读完这一页。**
>
> 这里列的是**我实际碰过、并且知道后果**的操作。
> 分成三档：☠️ **不可逆** / ⚠️ **可能弄哑** / ⚡ **会崩会重启**。
>
> 每条给三样东西：**为什么危险** / **判据**（怎么知道出事了） / **怎么退**。

---

## 一条总原则

> ### 这台设备的"身体"是一整套还活着的服务。你动的每一处，都可能是别人的地基。

我在这上面吃过的最大的亏，都是**以为某样东西是垃圾、结果它是地基**。

所以我的做法一直是：**能不碰就不碰；非碰不可，先想好怎么退。**

---

## ☠️ 第一档：不可逆

### ① 刷写裸 NAND

**这是什么**：设备是 **256MB 裸 NAND**（没有坏块管理芯片），分 **12 个区**，
而且有**双份 rootfs** 和三份引导程序。

**为什么危险**：

- 裸 NAND 有**坏块**，写得不对就是**永久损坏**
- 分区表是**厂商自己排的**，双 rootfs 之间怎么切换我**没有完全逆清**
- ★ **一旦写坏引导那几份，设备再也起不来**

**判据**：设备**完全无响应**、串口无输出。

**怎么退**：

- 主控（全志 R16）有 **FEL 模式**——这是厂商的**底层烧录/救砖通道**，能救
- ★ 但 FEL **本身也是高风险操作**（要用专用工具、要走 USB、写错了更惨）
- **我的建议：如果你的固件是好的、只是想换脑，那根本不需要碰 NAND。**
  我到最后也没刷过它——**改造完全不需要动 NAND**。

---

### ② 把 `.so` 装到了错的地方（后果不可逆的是"你以为它在工作"）

严格说这不是"弄砖"，但**不可逆的是你的判断**——

放在外挂存储上的注入库会被**静默忽略**：不报错、进程照跑、**钩子根本不在**。

**为什么危险**：你会基于"它应该在工作"去排查别的地方，
可能查上一整天，而且**越查越觉得是自己代码写错了**。

**判据**：
```
grep <你的库名> /proc/<那个进程的pid>/maps
```
有输出 = 在；没输出 = 不在。

**怎么退**：把库放到**根文件系统**里（不能是外挂存储）。

★ 根本原因是个**开机时序**问题：原厂语音进程在**开机 5.6 秒**就起来了，
而外挂存储要 **8.2 秒**才挂上——那一刻你的库**还不存在**。

---

## ⚠️ 第二档：会把机器弄哑（有一部分是"永久哑"）

### ③ 盲写 LED 那条串口

**这是什么**：主控通过一条串口（AT 命令）驱动一颗 MCU。

**为什么危险**：
★ **那颗 MCU 不只管 LED。它同时还管**：

- **音量旋钮的采样**（ADC）
- **触摸按键**

**也就是说：你往这条串口上随便写字节，可能顺带把音量改了、或者伪造出一个触摸事件。**

**判据**：音量莫名其妙变了 / 设备像是"被按了一下"。

**怎么退**：

- 没有"撤销"。只能发正确的命令改回去
- ★ **正确姿势**：
  1. **一次只发一个**已知的命令码
  2. **先发一个"阴性对照"**（一个已知无副作用的码）验证你的发送链路
  3. **有人在设备旁边看着**
  4. **事先想好**：这个码如果效果和预期不一样，我下一步怎么办

> 我为了摸 LED 命令码专门写了带"时间表"的探测脚本——
> **打印一张时间表，让人站在设备前面拿表对照**。
> 因为这一路**没法自动化验证**，只能靠人眼。

---

### ④ 改音频 DSP 的固件 / 灌 EQ

音频 DSP（ADAU1761）上有 EQ 预设，可以通过命令灌进去。

**为什么危险**：

- 那是**运行在 DSP 上的固件级操作**，不是普通参数
- 写坏了**整条音频通路就没了**——而且是**开机就坏**，不是运行时坏

**判据**：音频完全不通，`amixer` 读控件异常或读不到。

**怎么退**：★ **重启可能让 DSP 重新加载固件，也可能不会**——
**我没有完整验证过**，所以我的做法是：**不碰**。

> **我的态度**：EQ 是"锦上添花"，风险是"整机变哑"。**这个交换不划算。**

---

### ⑤ 独占声卡

**为什么危险**：原厂的唤醒引擎正**独占**着麦克风。

**你抢过来 ⇒ 它立刻瞎 ⇒ 唤醒词永远叫不醒 ⇒ 整台设备变砖。**

（这条是[03 章](03-隔离原厂那套.md)的核心，我在这里再列一次，
因为**"我是 root 我为什么不能开声卡"是几乎每个人的第一反应**。）

**判据**：喊唤醒词，灯环**不再有任何反应**。

**怎么退**：把占用还回去、重启原厂语音服务。

> ★ ★ 注意"重启语音服务"本身也有前置条件，见下面第 ⑧ 条。

---

### ⑥ 把音量拉满

**为什么危险**：**这是物理伤害，不是数据伤害。**

台面上的小音箱，**满刻度输出是能伤听力的**，尤其是它离人近的时候。

**判据**：不用判据——**别拉满**。

**怎么退**：听力损伤不可逆。**所以这条没有"怎么退"。**

> ★ 我的规矩：**改音频相关的东西，一律用设备当前的音量，绝不在播放路径上动音量。**

---

### ⑦ "守护脚本崩了就永久瘫痪"

这不是某个操作，而是一个**必须遵守的写法规范**。

**为什么危险**：我写过这样的单实例锁：

```sh
mkdir "$LOCK" || exit 0     # ❌ 致命写法
```

**问题**：脚本里**没有任何地方删这个锁**。

于是一次 `kill -9`（内存不足、手滑、系统强杀）就把锁**永久留在那儿** ⇒
**这个守护再也起不来，而且一声不响**。

**真实后果**：设备**哑了几个小时**才被查出来——
因为那个守护正是负责扳回音频通路的那个。

**判据**：守护进程的日志**很久没有新行了**（但进程"看起来"应该是在跑）。

**正确写法**：

```sh
# 锁里放 pid，用 /proc/<pid>/cmdline 核实那个 pid 真的是本脚本
# ⇒ 陈旧锁自动抢过来
```

> **宁可重复跑一次，也绝不再"永久瘫痪"。**
> ★ 这个模式的教训是通用的：**任何"崩溃后不会自动恢复"的锁，都是定时炸弹。**

## ⚡ 第三档：会崩、会重启、会死锁

### ⑧ 重启原厂语音服务前，必须先确认前置条件

**为什么危险**：原厂语音服务**依赖 D-Bus 环境**。
如果总线环境没准备好就去重启它，**设备会硬重启**——不是优雅重启，是**直接挂**。

**判据**：你发出重启命令，然后**设备整个重启了**。

**怎么退**：等它起来。★ 但**别在循环里试**——那会变成**重启循环**。

**正确做法**：重启前**先验证总线在那儿**（能列出会话总线、能通一条只读命令），
验证通过再动手。

---

### ⑨ 一个"一调就死锁"的调试接口

设备上有个调试/控制类接口，**调用它会让某个服务直接死锁**。

**为什么危险**：死锁是**不可恢复**的——那个服务再也回不来，除非重启它。

**判据**：调用之后那个功能**永久无响应**，但进程还在、不报错。

**怎么退**：重启那个服务（★ 但那又要满足第 ⑧ 条的前置条件）。

> ★ 我的做法：**既然知道它一调就死锁，就把它写进"绝不再调"清单里。**
> **不要因为"我想再确认一次"去调它。**

---

### ⑩ 直写进程内存改运行态

**这是什么**：通过 `/proc/<pid>/mem` 直接**读写另一个进程的内存**。
理论上可以不重启进程就"改掉"它的某个变量——**非常有诱惑力**。

**为什么危险**：

- **地址写错 = 那个进程立刻崩**
- 而这些进程是**地基**（见第 ⑤ 条）
- 而且地址**每次运行都不一样**

**判据**：目标进程消失（段错误）。

**怎么退**：重启那个进程——**但有前置条件**（第 ⑧ 条）。

> ★ 而且我做这件事时踩过一个**读数陷阱**：
> 读 `/proc/<pid>/mem` 想看某个字节，
> ★ **不能用 `hexdump -C`**——它会把一整段**全零**坍缩成一行 `*`，
> 于是**真实存在的 0x00 被误读成"读不到"**。
>
> **正确做法**：`hexdump -e '1/1 "%02x"'`，一个字节一行。**别让工具替你做省略。**

---

### ⑪ 重新映射 / 覆盖系统文件时的三个细节

| 细节 | 后果 |
|---|---|
| 推送文件**丢掉可执行位** | 下次开机**起不来**，只报 `rc=126`（"权限不够"），**看起来像"没生效"** |
| 换正在运行的脚本**不是原子替换** | 进程可能读到**半个文件** |
| 用 `kill $(pidof xxx)` 重启服务 | ★ **可能把整套网络搞挂**（有的守护不会自愈） |

**正确做法**：

- 换可执行文件后**补 `chmod`**
- 用**先写临时文件再 `mv`** 的方式替换
- 重载配置**发信号**（比如 `SIGHUP`），**不要盲杀**

## 几个"看起来是危险操作、其实不用做"的

这一节是省钱省时间的：**下面这些我一度以为必须做，后来发现根本不用。**

| 事情 | 为什么不用做 |
|---|---|
| **刷固件** | 整个改造**不需要动 NAND** |
| **伪造升级服务器** | ★ **不可能**——它的升级流程里**证书校验排在签名前面**，你过不了那一关 |
| **杀掉原厂进程** | 它们同时提供唤醒/播放/灯效，**你分不清垃圾和地基** |
| **抢声卡** | 有 D-Bus 那条路，**又短又稳** |
| **改 App 重新打包** | 我们那条路**根本不经过 App**（详见 [08 章](08-路线更正表.md)） |

## 一张速查表

| 操作 | 档 | 一句话 |
|---|---|---|
| 刷 NAND | ☠️ | 不需要做；要做先想好 FEL 救砖 |
| 注入库放错位置 | ☠️ | 不报错，但你的判断从此是错的 |
| 盲写 LED 串口 | ⚠️ | 同颗 MCU 还管音量和触摸键 |
| 灌 DSP / EQ | ⚠️ | 写坏 = 开机就哑，且**退路我没验证过** |
| 独占声卡 | ⚠️ | 抢过来 = 唤醒永久瞎 |
| 音量拉满 | ⚠️ | 物理伤害，不可逆 |
| 锁不删 | ⚠️ | 守护永久瘫痪，且不报错 |
| 重启语音服务 | ⚡ | 先验总线，否则设备硬重启 |
| 那个调试接口 | ⚡ | 一调就死锁，**别再调** |
| 写进程内存 | ⚡ | 地址错 = 崩；读数别用 `hexdump -C` |
