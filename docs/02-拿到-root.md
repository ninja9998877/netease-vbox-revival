# 02 · 拿到 root

> ★ **好消息：这根线一插上就是 root。不用拆机、不用焊、不用短接。**

这是整件事里最幸运的一环。如果这一步要拆焊，我大概一开始就不会做了。

---

## 你需要的东西

- 一根 **Mini-USB** 线
- ★ **注意是 Mini-USB，不是 Micro-USB**，更不是 Type-C
  （这个年代的设备很多用 Mini，**别买错**）
- 一台电脑（Linux / macOS / Windows 都行，只要装了 adb）

---

## 步骤

### ① 找到那个口

音箱上有个 **Mini-USB 口**，一般是给**维修/调试**用的，
平时用户根本不会用到它。插上。

### ② 看设备有没有被认出来

```bash
adb devices
```

★ 如果列出来了，**直接就能开 shell，而且是 root**：

```bash
adb shell
# 提示符就是 # ，不是 $
```

**不需要 `su`，不需要解锁，不需要任何提权步骤。**

> ★ 我第一次看到这个的时候愣了几秒——**这也太容易了**。
> 后来才明白原因：这是**开发板方案**（主控是一颗全志的芯片，
> 而全志给厂商的参考设计里，调试口本来就是开着的），
> **厂商没有把它关掉**。

### ③ 确认你真的是 root

```bash
adb shell id
# uid=0(root) gid=0(root)
```

### ④ 看看这是什么系统

```bash
adb shell 'cat /etc/os-release; uname -a'
adb shell 'mount | head'
```

★ 你会看到这是一个**很轻量的嵌入式 Linux**（不是常见的发行版），
文件系统是**只读的系统分区 + 一个可写的覆盖层**。

**这一点很重要**：这意味着

- ✅ 你的改动**能落盘**
- ⚠️ 但**系统分区本身是只读的**，改它要走覆盖层或者改可写分区

---

## ★ 一个特别提醒：那个调试口也是"后门"

`ttyS0` 是一个 **115200 的根 shell**。

**意味着**：任何能物理接触这台设备、并且有串口线的人，**都能拿到 root**。

> 对一台**放在自己家里的音箱**来说，这没什么。
> 但你应该**知道**这件事——尤其是如果你打算把改好的设备送人或转卖。

★ 我提这个不是吓唬人，是因为**这是这套方案的一个固有属性**：
**它没法防止物理接触者拿到 root。** 如果你需要防，那得另想办法。

---

## 关于 FEL 模式（★ 先别碰）

全志主控有一个**底层烧录/救砖通道**，叫 **FEL**。
进入之后，电脑上能看到一个特定的 USB 设备（厂商 ID `1f3a`），
可以用官方工具直接**读写芯片**。

★ **它是你刷坏了之后唯一的救命绳**——所以**知道它存在**很重要。

★ **但我的建议是：不要碰它。**

- 它能**救砖**，也能**造砖**，而且是**最深的那种砖**
- ★ **整个"换脑"改造从头到尾不需要它**
- 我写过一个小脚本蹲它（因为这个模式**只活几秒**，人工反应不过来），
  **而且只做只读动作**（读芯片型号、读芯片 ID），**绝不 write、绝不 exec**

> **如果你只是想换脑，那就永远不需要打开这扇门。**
> 把它当成**保险**，不是**工具**。

---

## 拿到 root 之后，先做这三件事

### ① 把原始状态备份下来

★ 在你改任何东西**之前**。

```bash
adb pull /mnt/UDISK/            # 可写分区整个拉一份
adb shell 'mount; ls -la /'     # 记下挂载情况
adb shell 'cat /proc/mtd'       # 记下分区表
```

**理由**：设备上有个可写分区，**你迟早会改到它**。
有备份 = 随时能对照"原来是什么样"。

### ② 确认哪些是"活的"、哪些是"死的"

```bash
adb shell 'ps w'                # 看有哪些进程
adb shell 'netstat -antp'       # 看它想连哪
adb shell 'logread | tail -50'  # 看它在抱怨什么
```

★ 你会看到它**反复尝试连一些已经不存在的服务器**。**这就是它"废了"的样子。**

### ③ 把这台设备当"别人的机器"对待

★ 我的习惯：**动手之前先假设"我可能会把它弄坏"**，
然后想清楚**每一样我打算改的东西，改坏了怎么退**。

> 这个习惯让我在[危险清单](07-危险操作清单.md)里列出的那些坑上，
> **只丢了时间，没丢设备**。

---

## 关于可写分区的三个坑

拿到 root 之后你会很自然地往可写分区里放东西。**有三个坑要先知道**：

| 坑 | 后果 |
|---|---|
| **有的存储挂载得晚** | ★ 开机早期**还看不到它**——如果你的程序在那之前要读它，会**读不到**（而且不报错） |
| **推送文件会丢权限** | ★ 尤其是**可执行位** ⇒ 下次开机起不来，只报"权限不够" |
| **改动可能不持久** | 有些地方的文件系统**重启后恢复原状** |

★ **验收方式**：**推完就重启一次，再看它在不在。**
别等到"全都做完了再一起测"——那时候你已经分不清是哪一步的问题。
