# 01 · 这台机器是什么

> 在动手之前，先搞清楚你在跟什么东西打交道。

## 身份

我拆开看过，也从系统里读出来过：

| 项 | 值 |
|---|---|
| **型号** | **网易三音云音箱**（VBox） |
| **上市** | 约 2018 年，**众筹**上市 |
| **主控** | **全志 Allwinner R16-J**（4×Cortex-A7 + Mali400MP2） |
| **内存** | 512MB DDR3L |
| **存储** | ★ **256MB 裸 NAND**（TSOP-48 封装，无坏块管理芯片） |
| **无线** | 博通方案，**只有 2.4GHz** |
| **蓝牙** | 4.1，只做 **A2DP Sink**（当蓝牙音箱用） |
| **功放** | TI 单声道功放 |
| **音频 DSP** | ADI ADAU1761（麦克风挂在它上面） |
| **麦克风前端** | CX20810（★ 注意：**它不是回声消除器**） |
| **唤醒引擎** | 第三方方案（`duilite` / `fespa`），**跑在本地** |
| **灯** | 一个可**按角度寻址**的灯环 + 一块 **9×9 单色点阵** |

★ 一个提醒：**同款外观可能有不同批次**。
上面的信息是我这台实测出来的，**你的那台未必完全一样**。
动手前先自己核一遍（[02 章](02-拿到-root.md) 有方法）。

---

## 系统长什么样

- **一个轻量嵌入式 Linux**，不是常见的桌面发行版
- PID 1 是一个**进程管理守护**（不是常见的 `systemd`、也不是纯 `init`）
- 文件系统是**两层叠加**：

```
只读的系统分区   ← 出厂固件，通常不动
      +
可写的覆盖层     ← 你的改动落在这里
      =
   你看到的 /
```

★ **这个结构决定了你的改动风格**：

- ✅ 你**能**改东西、**能**落盘
- ⚠️ 但系统分区是**只读的**，改它要么走覆盖层，要么改可写分区
- ⚠️ 而**可写分区挂载得比较晚**——这个时序坑我踩过（[05 章](05-音频链路真相.md)）

---

## 它为什么"废了"

★ 先说结论：**硬件一点没坏。它是被后端拖成砖的。**

这台设备的**架构选择**是它变成砖的根本原因：

> ### 它的耳朵、大脑和嗓子，**几乎全在云端**。

具体分工是这样的：

| 能力 | 在哪 |
|---|---|
| 唤醒（听到唤醒词） | ✅ **本地** |
| 语音识别 | ☁️ **云端** |
| 对话理解 | ☁️ **云端** |
| 语音合成 | ☁️ **云端** |
| 音乐内容 | ☁️ **云端** |
| 播放器 / 功放 / 灯 | ✅ **本地** |

**看出来了吗**：它**能听见你喊它**（本地），
但**听见之后要干什么，全得问云端**。

### 所以云一端停，它就只剩一个反应

- 你喊唤醒词 → 灯环**亮一下**（因为唤醒是本地做的）→
  然后它把音频**上传到已经不存在的服务器** → **卡住 / 失败** → **什么也不发生**
- 后台**反复重连**，日志刷屏，**CPU 一直被占着**
- 配套的手机 App **从应用商店下架**了 ⇒ **连配网入口都没有**
  （★ 这意味着：**就算它还能连 Wi-Fi，你也换不了 Wi-Fi 密码**）

★ 这是**没有本地降级方案**的典型后果。
厂商在架构上把"能不能用"这件事，**完全托付给了自己的服务器**。
服务器一停，设备就跟着一起"停"——**尽管它本身完全健康**。

---

## 但这台机器留了两条活路

★★ 这是我后来才发现、也是整个改造能成立的**前提**：

### 活路一：唤醒是**本地**的

唤醒引擎**跑在设备上**，不依赖云端。

★ 这一条价值极大——意味着**它还能听见你**。
**耳朵还在。**

### 活路二：设备内部是一张**本地的服务网**

设备内部不是一个大程序，而是**一堆互相通话的小服务**：

- 播放器
- 总控
- 蓝牙
- ……

它们通过一条**本地的进程间通信总线**互相说话，**跟云端一点关系都没有**。

★ 这意味着：**嗓子也还在**（只是没人指挥它了）。

---

## 所以整个改造的思路就一句话

> ### 换掉它的"云脑"，但**原厂的身体一寸不动**。

```
☁️ 网易云端大脑          →  ❌ 换掉（本来就死了）
─────────────────────────────────────────────
👂 唤醒引擎（本地）       →  ✅ 保留，直接用
🎤 麦克风（本地）         →  ✅ 保留，我在旁边接一份
🔊 播放器（本地）         →  ✅ 保留，我借它出声
🕹️ 控制服务网（本地）     →  ✅ 保留，我用它控制灯和状态
```

★★ **这四行是整份文档的地基。**
后面所有章节讲的都是"**怎么在不碰这四样的前提下，把脑子换掉**"。

> ★ 而这个思路**和大多数人的第一反应是相反的**——
> 第一反应通常是"厂商不管了，那我把它的进程杀掉、把资源抢过来"。
> **那条路会直接把设备弄砖。** 详见 [03 章](03-隔离原厂那套.md)。

## 你现在应该知道的

| 问题 | 答案 |
|---|---|
| 硬件坏了吗？ | **没有。** 它只是后端没了 |
| 需要刷机吗？ | **不需要。** 整个改造不碰固件 |
| 需要拆焊吗？ | **不需要。** 一个调试口就能进 root |
| 改坏的风险？ | **有**，但都在[危险清单](07-危险操作清单.md)里，可以避开 |
| 最难的部分是什么？ | ★ **不是写代码，是"搞清楚哪些东西不能碰"** |
