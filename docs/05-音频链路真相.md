# 05 · 音频链路真相

> [03 章](03-隔离原厂那套.md)讲了"为什么不能抢麦克风和声卡"。
> 这一章讲**具体怎么做到的**——包括几个不看源码绝对想不到的坑。

## 一、麦克风：钩住它的读取函数

### 先想清楚为什么要截

我一开始以为截麦克风是为了"万一网易关服了还能自己听"。**不是。**

真正的理由是：**打断（barge-in）**。

- 如果我只从系统的 D-Bus 总线上看事件，那我要等到**"最终识别结果"出来**才知道有人说过话
- 而那是**秒级**之后的事
- 但"主人开口了，你停下别说了"这件事，要求的是**毫秒级**

所以必须拿到**实时音频流**才行。这是整件事的硬前提。

### 为什么不能抢声卡

我先试了最直接的办法：`arecord` 直接录。

```
arecord: ... Resource busy
```

麦克风阵列被原厂的语音进程**独占**了。

我是 root，**抢得过来**。但抢过来的后果是：

> 原厂的唤醒、回声消除、语音识别**全部报废**。
> **那是把音箱弄哑，不是给它加耳朵。**

### 于是：钩函数，拷一份

思路是**在动态库层面把它的读取函数换掉**：

1. 用 `readelf` 看原厂那个语音进程的**导入符号表**——它动态链接了标准 ALSA 库，
   表里明确有 `snd_pcm_readi`
2. 顺便发现：mmap 相关函数的**调用计数是 0** ⇒ 说明它没走 mmap 那套，走的就是 `readi`
3. 我写一个同名的 `snd_pcm_readi`，用 `LD_PRELOAD` 排在前面
4. 我的实现：**先调真函数拿到数据 → 拷一份发走 → 原样返回**
5. 对原厂进程来说，**什么都没发生**——同一份数据、同一个返回值

### 怎么拿到音频格式

音频的采样率、声道数、位宽，我不是去"问"声卡，而是**在它自己配置参数的那一刻顺手读**。

- 它配置格式时会调 `snd_pcm_hw_params`，那一刻参数对象**刚被填好**，格式是确定的
- 比主动去查一个"别人可能还没配完"的句柄**时序上可靠得多**

★ 真机格式实测：**96000 Hz × 2 声道 × S24_LE**（每秒 768 KB 的持续上行）。

## 二、为什么必须在钩子里做滤波（这是被逼出来的）

拿真录音量了频谱之后我才明白，**不滤波根本不能用**：

| 频段 | 电平 |
|---|---|
| 人声（300–3400 Hz） | **-85.7 dBFS** |
| 24–48 kHz 的"超声垃圾" | **-70.4 dBFS** ← **比人声还高 15 dB** |

那簇超声垃圾是 **96k 采样时钟的 1/3 分频串扰**（32 kHz 附近一簇谱线），来自硬件本身。

**问题在于**：我要把 96 kHz 降到 16 kHz。如果不先低通就直接抽取，
这段强 15 dB 的超声会**整个混叠折叠回 0–8 kHz** —— 正好**糊在人声上**。

另外还有几根低频强线（市电嗡声那一类，也在 -75 dBFS 上下）——它们不混叠、
会原地留下，**白占 14 dB 的动态范围**。

### 所以钩子里的处理链是

```
24 位输入
  → FIR 低通（抗混叠）
  → 6 倍抽取        （96 kHz → 16 kHz）
  → 4 阶巴特沃斯高通（隔直，铲掉市电嗡声）
  → int16 输出
```

**实测量化效果**：人声带只掉 **0.2 dB**，25–35 Hz 掉 **51 dB**。
上行数据从 **768 KB/s 降到 64 KB/s**（砍到 1/12）。

> ★ 一箭三雕：省带宽、铲掉市电嗡声、铲掉那簇怪音。
> 而且这套是**在真录音上跑定点实现**验证过的，不是纸上算的。

## 三、几个不做就会静默失败的硬约束

这一节是整章的精华。**下面每一条，违反了都不会报错，只会"看起来没生效"。**

### ① 一个头文件都不 include，连 libc 都不链（`-nostdlib`）

设备用的是 **musl**。如果你的 `.so` 带进来一份自己的 libc，
会把 `malloc` 之类的符号**顶到全局作用域**，把主程序那份**顶掉**——**灾难性的**。

所以这个文件里所有外部符号（`dlsym`/`socket`/`sendto`/`getenv`…）
**只声明、不定义**，运行时由动态链接器从**进程自己那份 musl** 里解析。

### ② 全用整数定点，一个浮点都不碰

同理：任何**被你自己带进来**的符号都会污染进程全局作用域。

- `double` 会引入 `__aeabi_dadd` 之类的 libgcc 符号
- 变量除法会引入 `__aeabi_idiv`

所以：系数全部 **Q20 定点**（int32 存、int64 累加），除法走自己写的整数除法。
编译完用 `nm -u` 确认未定义符号只剩 musl 里那几个。

### ③ ★★ 绝不能把 `.so` 放在外挂存储上

**这条害我最久。**

- 原厂语音进程在**开机 5.60 秒**启动
- 而外挂存储要 **8.2 秒**才挂载完
- 那一刻，放在外挂存储上的 `.so` **还不存在**
- musl 的动态链接器遇到不存在的 `LD_PRELOAD` 目标时——**静默忽略**（不报错、进程照跑）

**结果**：麦克风在跑、进程一切正常、**但钩子根本不在**，一个包都不发。

> **正确做法**：`.so` 只能放**根文件系统**里。
>
> **判据（别靠猜）**：
> ```
> grep mictap /proc/<那个进程的pid>/maps
> ```
> 有输出 = 钩上了；没输出 = 没钩上，回去查路径。

### ④ 绝不阻塞音频线程

发包用 **UDP + 非阻塞**。socket 队列满了就**丢包，绝不等待**。

> 这是麦克风通路。**宁可丢我们这份副本，也绝不能让原厂那边卡住一帧。**

### ⑤ 留一个急停开关

设备上只要存在某个特定文件，就整个不发（**不用重启服务**）。
排查的时候能救命。

## 四、出声：只有一条路

出声这条路我从头到尾**没碰过声卡的播放侧**。

```
我的电脑合成语音 → 起一个本地 HTTP 服务放着这个 mp3
                → 通过 D-Bus 命令原厂播放器："去播这个 URL"
                → 设备自己来下载、解码、播放
```

- **命令是 D-Bus 调用**，参数只有 **URL 和播放器 ID**
- 设备**自己发起 HTTP 请求**来取文件
- ★ 好处：能顺便控制码率、支持**断点续传**、还能就近观察"它到底来取了没有"
  （**"它来取了"就是"成功"的判据**）

### 我一度想走 DLNA，后来放弃了

设备本身是个 DLNA 渲染器，用标准协议推流看起来更"正规"。**我试过，放弃了。**

原因不是它不能用，而是**用起来处处别扭**：

- 有一堆端口和发现协议参与其中，**任何一环不对就整个不出声**，排查面太大
- 而设备内部的播放器**一直都在**，直接命令它**又短又稳**
- ★ 后来发现：DLNA 的端口**全部 ConnectionRefused**、发现协议 **0/6 响应**，
  这其实是**正常现象**、不是故障——但这一点坑了我很久，因为我会以为"DLNA 坏了"

> **结论**：能直接命令内部播放器，就别去绕标准协议。
> 少一层，就少一层能坏的东西。

## 五、麦克风采样率的一个隐藏坑

设备上有个初始化路径会把采样率**从 48000 覆盖成 16000**。

★ 这个坑的可怕之处在于：**包头里写的采样率**和**真实流的采样率**可能对不上
（比如包头说 16000，实际流是 48000）——你拿到的音频会**变调、变速**，
而所有日志看起来都是对的。

**判据**：别信包头，**拿真音频去量**（比如数一个已知时长的人声有多少个采样点）。
